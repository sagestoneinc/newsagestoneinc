# SageStone Inc. Website Strategy and SEO Package

## Step 1: Current Site Audit

The local repository was empty: no committed files, no existing page templates, no CSS system, no sitemap, and no content architecture. Because no current SageStone implementation was available in the workspace, the audit is based on the current build state rather than a prior live codebase.

Key gaps addressed:

- Messaging: no existing local copy to explain SageStone as a premium remote operations partner rather than a generic VA provider.
- Design/UI: no visual system, reusable sections, responsive navigation, forms, or conversion-ready layouts existed.
- UX/conversion: no homepage narrative, service routing, trust strip, proof area, FAQ, or repeated CTA structure existed.
- Information architecture: no `/services` hub, service detail pages, `/about`, `/contact`, or future `/resources` hub existed.
- SEO: no crawlable commercial service pages, metadata, canonical paths, internal linking, sitemap, robots file, or schema-ready FAQ content existed.
- Premium repositioning: the new site reframes SageStone around reliability, organized execution, real estate/property support, and remote operations capacity.

## Step 2: Revaya Benchmark Translation

Revaya was used as a quality benchmark, not a template. The useful patterns to borrow are premium page pacing, calm hero clarity, strong whitespace, polished service cards, early trust framing, repeated CTAs, and scannable B2B storytelling.

What not to copy:

- Exact layouts or wording.
- Any proprietary brand language, visual compositions, or naming conventions.
- A cold enterprise tone that would make SageStone feel less warm and human.

SageStone interpretation:

- Warmer editorial palette using Warm Ivory, Sage Mist, Olive Sage, Stone Taupe, Soft Beige, and Charcoal Ink.
- Playfair Display for premium editorial headings and Lato for clear service-business readability.
- More niche emphasis on real estate and property management support.
- More operational language: workflows, follow-up, SOPs, tenant communication, CRM upkeep, admin relief.

- Service pages: rank for commercial keywords and convert high-intent visitors.
- About: build trust, philosophy, and brand differentiation.
- Contact: qualify inquiries and set expectations.
- Resources: prepare a crawlable hub for future topical authority.

### Homepage Narrative

Clarity, trust strip, who we help, core services, why SageStone, how it works, business outcomes, real estate/property management niche, proof-ready section, FAQ, final CTA.

### Conversion Strategy

- One dominant CTA pattern: “Book a Discovery Call.”
- Secondary CTA: “Explore Services.”
- Trust appears early through operating-model language and buyer-fit signals.
- FAQs handle scope, tools, onboarding, pricing, and niche fit.
- Contact page clarifies best-fit buyers and next steps.

### Metadata

Metadata is implemented in each HTML file with page-specific title, meta description, canonical URL, and OG title/description where appropriate.

### On-Page Structure

Each page uses one H1, section-level H2s, clear service H3s, scannable lists, internal links, and FAQ blocks that can be converted into JSON-LD FAQ schema.

### Schema Suggestions

- Organization schema on the homepage.
- Service schema on every service page.
- FAQPage schema for each FAQ section.
- BreadcrumbList schema if deeper service/content hierarchies are expanded.
- LocalBusiness should be used only if SageStone wants location-specific positioning.

### Internal Linking

- Home links to service overview and all core service pages.
- Services links to all service pages.
- Service pages link to contact and related service pages.
- Footer links create persistent crawl paths.
- Real estate support is surfaced in primary navigation due to strategic priority.
